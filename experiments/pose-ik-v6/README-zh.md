# 人体关节约束实测：v6 实验候选

结论：保留 v5.2，当前约束候选不应作为改进版本替换。正式 OpenSim 4.6 引擎与受约束 IK 确实运行，但这套简化人体模型未稳定减少速度尾部，部分动作被压缩，转身观测残差偏大。这是一个可复现的负结果。

## 实际实现

- 官方 PyPI OpenSim 4.6，MediaPipe Python 1.1.0 CPU/XNNPACK。未引入 Mink、OpenCap Monocular、SMPL。
- 自建简化人体模型：25 自由度，6DOF 自由根、3DOF 躯干、左右肩/髋各3DOF、肘/膝各1DOF。使用12个主要关节中心点。
- 这不是标准 Rajagopal 模型，也不是经过个人标定的临床肌骨模型。身体质量/惯量是无动力学意义的占位值；无肌肉、接触、足底贴地约束或扭矩推断。腕/踝只作为末端标记，无独立关节/脚掌方向建模。
- 由最初30次实际输入中置信度>=0.7的有效骨段长度取中位数，随后固定。某骨段不足5次有效样本用显式默认长度；每项记录样本数及是否fallback。前30次不产生约束拟合。
- OpenSim坐标为(x,-MediaPipe y,-MediaPipe z)。球关节使用OpenSim内禀XYZ参数；肘Pin轴为局部-x、膝为局部+x。左右镜像外展范围。范围只是工程假设，未逐人验证；参考src/opensim_ik.py中的coord_specs和交付的.osim。
- 除自由根以外，每个坐标同时设置range及clamped=true。无速度裁切、无额外时间平滑；上一帧姿态仅作求解初值。只有约束符合，不能推出观测正确。
- 观测权重：v5.2 measured为confidence²；uncertain为0.1×confidence²；lost、非有限点、显式缺失为0。零权重位置占位不作为观测。没有任何拟合点提升为新的measured。
- 原始33点、置信度、状态、帧身份完整保留；拟合仅12点另存。全部主要点丢失时隐藏，不输出伪观测。单点缺失的几何推断明确标记inferred_unobserved。

## 同源离线筛选

三段来自既有v5.2真实在线记录，约65秒运行包含重复源片段，不能当65秒独立动作。第一遍独立源片段的指标另列。排除前30次校准；有效比较只在相邻成功拟合、同clip和epoch、0<dt<=150ms且该关节两帧均measured的条件计算，缺失和跨loop不桥接。

|素材|拟合帧|P95观测残差|速度>6m/s raw→fit|IK P50/P95|
|---|---:|---:|---:|---:|
|fast|1879|4.08cm|151→176|5.14/14.89ms|
|slow|1591|6.84cm|40→62|2.27/8.92ms|
|turn|1582|20.33cm|315→390|5.48/15.66ms|

速度尾部是诊断代理，不是已确认的错误跳变；真人没有3D真值，观测残差也不是准确度。转身有3帧无pose，实际上是同一17.28秒源帧重复3次，求解器错误为0。所有边界误差仅浮点量级。

幅度采用每关节在同一measured集合上的XYZ各方向P05至P95跨度向量长度，没有逐帧重新对齐。fast主要肢端约98–103%；slow右踝88.8%，可能压掉正常幅度；turn右膝116.1%、左踝112.6%，部分幅度被放大。不能以“更平滑”宣称更准确。

## 独立控制

- 240帧同模型已知真值，含快速肢体动作、转身、躯干与根位移：平均marker误差0.23mm，幅度99.80–100.04%，最佳时延0帧。
- 冻结第一帧的负对照速度尾部为0，却明显丢失动作（幅度0），正确判为失败。
- 加入固定随机种子的2cm高斯噪声和7个25cm腕部尖峰：平均误差32.2→28.1mm，P95却55.7→56.4mm；不能宣称普遍鲁棒纠错。
- 缺失腕/踝10帧，推断误差最大37.7cm；重新观测后的第一帧恢复到预设容差。缺失推断不能当真值。
- 19个有界坐标逐一近边界运动，共1482帧，有9帧超过3.55mm工程门限，最大4.67mm。求解错误0、越界0。故也不能宣称所有无噪声动作均过关。
- 同模型真值只检验求解实现，不检验该模型是否符合真实人体；球关节轴向旋转无法由12个关节中心完整识别。
- audit/保存控制脚本、快照、源hash、合成数组、结果与mask/身份审计。

## 实时实测

在dot云机的实际浏览器，以原速1×播放三段视频，MediaPipe逐帧现场推理，2 waiting+1 inflight，RGBA传输。约束stage在相同单个inflight链内，额外HTTP和求解时间都真实计入端到端延迟。使用实际画布captureStream录屏，没有预计算、后期平滑或用离线处理速度伪装实时。

正式实时数据/录像、耗时及校准完整性见results与live-summary.json。录像同时保留源画面、raw观测及明确标记的约束拟合。录屏开销计入本轮结果，不能直接与无录屏或不同环境的旧成绩等同比较。软件端到端从源帧计划释放到绘制提交，不是屏幕光子时延。


正式65秒结果（slow / fast / turn）：

- 同帧更新Hz：24.18 / 23.89 / 23.75
- 实际成功拟合Hz（仍用整段65秒作分母，校准不计拟合）：23.72 / 23.43 / 23.25
- 原始12主关节均measured的有效Hz：23.28 / 15.48 / 17.63；拟合不增加该计数
- 软件端到端P95：77.77 / 77.51 / 82.00ms（包含录制开销）
- 新增纯IK求解P95：10.78 / 15.76 / 17.85ms
- 新增IK HTTP往返P95：18.74 / 22.52 / 24.77ms（已包含求解，不可再相加）
- 三段帧/PTS/状态错配均0；source waiting/stalled均0；最大2等待+1执行
- 每段前30次输出校准，11项骨长均有足够样本，无fallback。turn的3个no_pose保持丢失，不假造姿态。

这不是单变量对照的性能提升证明。原v5.2历史环境/录屏负载不同，故不直接用其旧P95相减当精确新增开销。纯IK与额外HTTP组成在本轮逐帧记录。

## 范围与后续

MediaPipe世界点是髋中心坐标，本实验没有证明真实世界平移、相机标定或绝对3D精度。补充2D映射只是不校准的一致性代理，且在raw前30帧拟合，会偏向raw，不能称相机重投影精度。

这一负结果只否定当前简化模型直接后处理候选，不能否定OpenSim或人体先验路线整体。若继续，应先用有可信3D真值的动作检验人体模型/观测定义与鲁棒损失，不能先增加平滑来追数字。保留v5.2作为稳定基线。

## 工程角度范围（度，非临床标准）

- root：XYZ旋转+XYZ平移均自由
- lumbar：XYZ分别[-90,90]、[-80,80]、[-60,60]
- shoulder L/R：X[-180,60]、Y[-100,100]；Z左[-40,180]、右[-180,40]
- elbow L/R：局部-x轴[0,155]
- hip L/R：X[-150,45]、Y[-60,60]；Z左[-40,80]、右[-80,40]
- knee L/R：局部+x轴[-5,165]

以上范围按OpenSim坐标参数实施，不能直接拿这些参数当准确的人体临床屈伸/内外旋角度。肩胛运动、前臂旋前旋后、膝平移等均被简化；大幅芭蕾动作尤其可能与此模型冲突。
