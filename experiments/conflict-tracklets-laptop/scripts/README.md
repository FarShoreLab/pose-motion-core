# 冲突轨段与前后端重连实验 · 2026-10-18

本轮没有通过集成门槛。开发篮球片段的因果保护比上一版增加了正确覆盖，但另一段篮球出现错误恢复，单人素材也有新增缺口；离线版没有纠正错误恢复。本分支保存失败结果，不替换基线，不接入 GVHMR / MediaPipe 共享 3D 推理。

用户提出的“人在冲突前后可识别，中间允许未知”的思路，在手选可靠端点的两个事件上可行。不过，可靠端点如何自动产生、真实竞争者如何进入联合匹配，仍是本次失败的关键。不能把 oracle 成功当成自动系统成功，也不能把当前实现失败当作对所有双端方法的否定。

## 开发片段：先看身份风险与覆盖

同一 207 帧输入、同一 YOLOv8x 检测与已有 yolo26n-ReID 特征缓存。只有这一种 ReID 编码器；没有第二编码器、重新检测、重新提取特征或新模型下载。

| 方法 | 正确目标 | 明确错人 | 遮挡歧义 | 未确认 | 正确覆盖 | 清晰目标误拒 / 121 |
|---|---:|---:|---:|---:|---:|---:|
| 原始 BoT-SORT，起始 ID2 | 101 | 0 | 4 | 102 | 48.8% | 54 |
| 上一版 gallery v3 | 83 | 0 | 0 | 124 | 40.1% | 65 |
| 新版无冲突保护 | 165 | 4 | 3 | 35 | 79.7% | 0 |
| 新版因果冲突冻结 | 126 | 0 | 0 | 81 | 60.9% | 26 |
| 新版离线轨段重连 | 51 | 0 | 0 | 156 | 24.6% | 70 |

“未确认”包括 provisional 与 unresolved，均不算有效目标观测。因果版实际身份状态为 confirmed 126、provisional 44、unresolved 37；候选几何状态为 observed 170、missing 37。那 44 个临时身份候选的框来自真实检测，但并不代表已知属于目标。

无保护版的 172 次确认中有 4 次明确错人（F104–106、F108）和 3 次歧义（F86–88）；明确错人风险 2.33%，把歧义也计入则为 4.07%。因果版本片段未发现错人，却丢掉了原始 BoT-SORT 已正确的 40 帧，同时新增 65 帧正确恢复，净增 25；相对上一版 v3 丢 2 帧、增 45 帧，净增 43。因果版相对无保护版丢 40 个正确帧，仅补回 1 帧，不能只用“零错人”称胜。

正确身份也不等于完整人体框：无保护版接受了 4 个截断的正确目标框，因果版 1 个，离线版 0 个。本轮没有关节点精度真值。

## 另一篮球：错误恢复得到逐帧确认

对 `r2_fast_basketball` 全部 204 帧进行了 AI 目视检查，并放大检查 F59 与 F70–74 的错误候选。

| 方法 | 正确粉衣目标 | 明确黑衣错人 | 未确认 |
|---|---:|---:|---:|
| 上一版 v3 | 9 | 0 | 195 |
| 新版无保护 | 204 | 0 | 0 |
| 新版因果保护 | 31 | 16 | 157 |
| 新版离线重连 | 0 | 0 | 204 |

因果版的 47 次确认只有 31 次正确，16 次是 F59–74 的黑衣、红短裤干扰者，持续 0.533 秒；确认中的错人比例为 34.0%。无保护版本片段的目标一直可辨认，但部分框含重叠人物，不能据此认证分割、骨架或一般鲁棒性。

F59 的恢复优化只有一行目标身份和一列黑衣候选 D2。真实粉衣目标 D0 仍在原始候选及临时轨道中，却因几何冲突不断重置“三个清晰帧”窗口，没有进入恢复候选集合。错误连接成本 0.487468，外观相似度 0.368987；两端都不匹配的成本为 0.7，形成了 0.212532 的排除间隔。这个间隔只比较错误边与 dummy，并没有比较被过滤的真实目标。保存全部原始候选，不等于在恢复优化里保留全部竞争者。F59–70 被错误确认的清晰观测还会更新目标模板，污染后续外观库。

离线版没有纠正上述错误：首帧目标有几何重叠线索，清晰轨段生成器没有创建含显式种子的轨段，因此目标路径为空。其 0/204 是种子传递机制失败，不是成功拒绝错人，更不是证明前后端方法不可行。

## Oracle 可行性：AI 端点标注，不是自动结果

在首次自动运行前，AI 目视选择冲突边界和冲突前后的可靠框。身份标签只用于验证；成本不读取颜色名称、数字跟踪 ID、左右次序。比较完整 keep/swap 排列与部分匹配，允许未匹配、生灭及人数不相等；缺少后端证据时不强制连接。

| 事件 | 冲突帧 / 时长 | 可靠前端末帧 → 后端末帧 | 联合最优与间隔 | 结论 |
|---|---|---|---|---|
| A 红衣 / 浅蓝交叉 | F21–30 / 0.333s | F12 → F42 | 正确交换，0.3030 | 可连接；需 F42 的未来证据 |
| B 红衣 / 亮蓝长遮挡 | F77–119 / 1.433s | F62 → F122 | 正确交换，0.2692 | 可连接；需 F122 的未来证据 |
| C 四人交叉 | F145–193 / 1.633s | F141 → F196 | 浅蓝与米色最优配对错误，0.04493 | 整组不确认 |
| D 片尾冲突 | F200–206 / 0.233s | F198 → 无 | 仅未匹配，无后端 | 未知，右删失 |

C 的红衣和亮蓝边在全局重优化后的排除间隔分别为 0.31217 与 0.28266，可单独保持；两个错误边的间隔只有 0.04493，被拒绝。这不表示四个人都恢复成功。端点框仍可能有边缘污染，并非完美分割。

原始 `oracle-v1` 的整组结果保留未改。在看见 C 的无关人物歧义后，增加“逐边全局排除间隔”诊断，并在自动实验前采用它；成本与阈值未改变。`oracle-v1-pair-certainty` 单独保存。不能把这一诊断改进写成预注册结论。自动运行之后没有按结果反复改阈值，配置中的风险间隔网格没有用于寻找最优阈值。

## 方法及时间证据

实时候选版只读取当前及过去缓存：局部几何/外观连续性形成微轨道；重叠、距离、局部分配歧义共同标记冲突。高 IoU 本身仅冻结模板，不足以宣布身份丢失。可靠轨段遇到冲突、强外观变化或歧义即切开。保留原始检测、重复框记录与逐帧状态。

恢复使用外观库、速度、方向、尺度及一对一部分分配；不把同一数字 ID 或左右位置当成身份真值。成本为 0.65 外观 + 0.20 运动 + 0.10 尺度 + 0.05 方向；每个未匹配端点代价 0.35，确认间隔 0.10，相似度下限 0.35。其他局部常数记录在冻结代码哈希中。三个清晰帧的确认至少需要 2 帧、66.7ms 的观测等待；首帧显式种子例外。

开发片段因果处理总耗时 0.4124s，无保护 0.2988s，差值约 0.1136s（0.55ms/帧）。因果单帧中位数 1.67ms、p95 4.09ms、最大 10.26ms。它们仅衡量已有缓存上的 CPU 关联计算，不含解码、检测、ReID、姿态或显示，不是端到端实时性能。

按 AI 冲突终点后首次连续三个正确帧的起点计，因果 A/B/C 恢复为 F37/F121/F194，距离冲突末帧 7/2/1 帧（233/67/33ms）；D 在片尾未恢复。三个后续标签仅用于事后确认稳定段，不作为因果算法输入。开发片段最长未确认段 38 帧。原始逐帧日志提供完整间断而非单一平均值。

离线版对清晰轨段进行一对一有向无环路径连接，全部目标输出只使用实际存在的框，没有插值或隐藏关节点。开发片段 28 条可靠轨段，连接求解 0.05255s；加因果轨段构建约 0.4650s。全片联合优化使用到 F206，所有离线记录明确写入该未来证据末帧，同时边记录另保留后端锚末帧。其目标链只到 F65：关键 13→22 连接的排除间隔 0.00952 被拒，之后不能跳过失败边恢复目标。不能把离线回填的 F35 误称为当时已经输出。

## 验证、范围与限制

六个有意义的关联单元测试通过：交换次序、dummy 生灭、空后端、平局、无关人物歧义、与小矩阵穷举等价。七段素材分别在 30/90/150 帧截断点验证因果前缀一致；输入缓存运行前后哈希一致。旧版提交 `c76521b983a05d86b684b45d57771c347b5524f0`、五个 Library 文件及 32 个冻结输入有独立存档记录。

开发片段复用上一轮全部 207 帧的 AI 目视标签，并对 11 个新选择补充上下文与放大框审查；第二篮球全部 204 帧本轮审查。都不是独立人工真值，不能报告标准 MOT IDF1/HOTA 或精确身份切换率。原 25fps 素材采样到 30fps 含重复源帧，不能把帧数当成独立统计样本。

这里是最小自定义试验，不是 GTA 或 StrongSORT 论文复现。GTA 采用先拆分混合轨段再连接的结构，并使用 SportsMOT 训练的 OSNet；本试验只有已有的 yolo26n-ReID 缓存，不能把论文结果归因于轨段策略本身。AFLink 的关联和 GSI 的插值是不同步骤，本轮没有实施 GSI，也不补不存在的观测。[GTA 仓库](https://github.com/sjc042/gta-link)、[GTA 论文](https://arxiv.org/html/2411.08216v1)、[AFLink 实现](https://github.com/dyhBUPT/StrongSORT/blob/master/AFLink/AppFreeLink.py)。

下一次若继续，应先修复两个结构问题：冲突组中的真实竞争者被清晰窗口过滤，以及首帧种子无法传递到后来清晰轨段。然后使用新的独立人工标注片段检验，重新审视编码器可分性。本轮不继续调阈值，不声称用户思路已落地成功。
